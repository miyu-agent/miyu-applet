## AP-23：安装包带上看门的小程序，钉的核心和网页跟到现在的 main

状态：已完成（2026-11-23，本机检查、三平台 CI、三平台打包和流水线里拆开核对都过了，见「结果」）。Windows、macOS 的安装包没有人手装过，见「要人手测的」。

### 目的

核心 LW-28 把「核心被强行结束时让它起的命令、扩展跟着走」的看门进程从沙盒助手里拆了出来，成了单独的小程序 `miyu-watchdog`，Unix 的发行包从三个程序变成四个（Windows 上核心进作业对象，不带它）。安装包带的核心要跟到这一步以后的版本，带的程序也要加上它：漏了不会坏，看门的会退回 `/bin/sh`，只是每次多花约 0.3 ms CPU、多占约 0.15 MB。

钉的核心同时带上这一轮轻量化的各步（排函数的清单补全、分配器、数据库连接的页缓存、SQLite 的小块内存池等）。

### 图纸改哪几节

- `desktop.md`「装在哪」：外壳旁边的程序多一个，Linux 那一行。

### 做法

1. `pins.toml`：核心钉到 `38a83e830dafad5c7362c9c16d66b039e3bc2fe8`，网页跟到它的 main `9690babccedb68208028be8b3efb1c0733024a43`；`Cargo.toml` 里 `miyu-client` 钉同一个核心提交，`Cargo.lock` 跟着变。
2. `packaging/stage.py`：带的程序照目标分，Unix 上多带 `miyu-watchdog`（`core_programs`）；许可证说明里的程序名单跟着改。
3. `packaging/linux.json`、`macos.json` 的 `externalBin` 加上它；`windows.json` 不加。
4. `.github/workflows/release.yml`：编核心时 Unix 上多编 `-p miyu-watchdog`；「包里的核心照常起得来」那一步跳过它（它不带参数才看门，带了参数退出 125）。
5. `packaging/tests/test_stage.py`：假的核心检出里加上它，加一条「只在 Unix 上带」的测试。

### 结果

- 本机：`cargo fmt --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace`（129 条）、`cargo xtask licenses`、`cargo xtask privacy`、打包的单元测试（3 条）都过。
- 流水线：CI 三个平台都过；打包的六个任务都过（完整的包 Linux、macOS、Windows 各一个，只装托盘的三个），拆开核对装好的样子那一步也过。Linux 那一台的日志里看得到编了 `miyu-watchdog`。
- 把流水线打出来的 Linux 的 deb 下回来拆开：`usr/bin/` 下有 `miyu`、`miyu-applet`、`miyu-extract`、`miyu-sandbox`、`miyu-watchdog`（362 kB）。单独起 `miyu-watchdog`、标准输入接空的：它杀掉自己那一组（退出码 137）；带参数时说用法。
- 用这个包里的核心在沙箱数据根里说一句带九次工具调用的话（本机假模型），核心放在 `strace` 底下只记它起过的程序：两条 `shell` 命令各起了一个 `miyu-watchdog`，没有退回 `/bin/sh`。
